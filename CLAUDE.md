# TailorbirdCV

Tailors the user's resume to a job description without inventing anything. A local web app (macOS, Windows, Linux) for anyone: who the resume is for (field, seniority, target roles, region, spelling, page limit, domain pack) is a setting (Settings → Your targets), never hard-coded. A gitignored `CLAUDE.local.md` may hold the owner's personal context.

## Non-negotiable rules
1. **Never invent.** Every claim in a tailored resume must trace to the master profile (`profile.yaml` in the data folder). No new numbers, tools, employers, scope, outcomes, or implied experience — not even "familiar with". If the JD wants something the profile lacks, **ask the user**; if they have no real experience, it stays a gap.
2. **Locked fields never change**: contact, employer, location, job title, dates, education, certifications, awards, languages. The renderer pulls them from the profile by id — never retype them.
3. **The profile changes only with the user's explicit confirmation of the exact wording.** (The first-run import shows the transcribed profile, flags anything not found word-for-word in the source file, and saves only when the user clicks Save.) New evidence gets `source: interview` or `source: prep_guide` and `in_base_resume: false`.
4. **Rephrasing is allowed** (reorder, merge, trim, mirror JD vocabulary) as long as the meaning, numbers and entities are unchanged and each claim cites its `sources`. Don't upgrade verbs ("contributed to" → "led") or scope ("team" → "organization").
5. `uv run tailorbirdcv check` must PASS before `build`. Bullets may only cite their own role's evidence; role header ids aren't citable. Fix violations by citing the right evidence or rewording; never by adding vocabulary or synonyms without the user's approval.
6. Personal data lives only in the data folder (`private/` in a checkout, gitignored; the OS per-user folder when installed). Never commit it, never paste it into tests or shipped files (`tailorbirdcv/data/`, demo, examples) — tests use `tests/fixtures/` (fictional, and not a lightly disguised owner: no real employers, places, numbers or project names from anyone's actual CV). `test_shipped_config_has_no_personal_data` reads the owner's private profile at test time (never copied anywhere) to check shipped config.

## Layout
- `tailorbirdcv/` — `schema.py` (models), `ingest.py` (docx → profile), `render.py` (docx in a theme), `themes.py` (resume designs), `factcheck.py` (blocking gate), `ats.py` (keyword coverage), `pdf.py` (Word/LibreOffice → PDF), `cli.py`.
- `tailorbirdcv/data/` (shipped in the package): `config/industries.yaml`, `config/tracks.yaml` — emphasis heuristics only, never facts; `templates/base.docx` — theme/page setup with empty body, no PII; `fonts/` (Gelasio, OFL); `words.txt.gz` (fact-check word list). Never put personal data here.
- `tailorbirdcv/paths.py` — where things live: bundled data, the built UI (`tailorbirdcv/web/` in a wheel, `web/dist/` in a checkout), and the user's data (`TAILORBIRDCV_PRIVATE`, else `./private` in a checkout that has one, else the OS per-user data folder via platformdirs).
- Packaging: PyPI name `tailorbirdcv` (command `tailorbirdcv`); `hatch_build.py` puts `web/dist` into the wheel as `tailorbirdcv/web` (run the web build first). `tailorbirdcv/doctor.py` backs `tailorbirdcv doctor` and `GET /api/doctor`. Version: the root `VERSION` file (hatch reads it; `[tool.uv] cache-keys` refreshes the editable install). Releases: bump `VERSION` on main → once CI passes, `.github/workflows/release.yml` (`workflow_run`) builds that commit, publishes to PyPI (trusted publishing) and pushes tag `vX.Y.Z`; it skips commits whose version is already tagged and refuses a lower version; the automatic path only runs when the repo variable `RELEASES_ENABLED` is `true`. A manual `vX.Y.Z` tag push still works (must match `VERSION`). `install.sh` (macOS/Linux, POSIX sh) and `install.ps1` (Windows PowerShell 5.1 + 7, ASCII only, never `exit`: it runs inside the user's shell via `iex`) install uv if missing, then `uv tool install --upgrade --python 3.13 tailorbirdcv` (`TAILORBIRDCV_PACKAGE` overrides) with `UV_MANAGED_PYTHON` and system certificates, fix PATH and start `tailorbirdcv serve`; they refuse while TailorbirdCV runs (Windows locks its files) and under sudo; CI's *One-line installer* job runs them piped against the commit's wheel. Licence: AGPL-3.0-or-later (`LICENSE`, the official text; `license` in `pyproject.toml`, so PyPI shows it); the name and logo aren't licensed (README → Licence); Settings → About links the source code, as AGPL §13 expects of a network service.
- `docs/brand/` — logo sources and brand rules (`logo.md`: palette, Outfit wordmark, usage). The web UI's tokens in `web/src/index.css` follow it (forest ink and masthead, rust accent, crimson for errors so they never read as the accent); `docs/logo.png`/`logo-dark.png` (README) and `web/public/apple-touch-icon.png` are rendered from those SVGs with Outfit. `docs/brand/how-it-works.svg` is the source of the README's diagram (`docs/how-it-works.png`, and `-dark.png` with `class="dark"` on the root), rendered at 2× with the UI's fonts (Outfit, Instrument Sans, Geist Mono); re-render both PNGs when the app's flow changes. `docs/brand/social-preview.svg` is the source of `docs/social-preview.png` (GitHub's social preview, 1280×640, uploaded by hand in the repository's Settings → General), rendered with the same fonts.
- `.claude/skills/profile` (`/profile`) and `.claude/skills/tailor` (`/tailor`).
- `private/` (the data folder) — `profile.yaml` (source of truth), `knowledge.yaml` (memory: past gap answers + approved style preferences, **never citable**), `source/`, `applications/<company>/<yyyy-mm-dd>_<role>/` (id `<company>~<yyyy-mm-dd>_<role>`; `meta.json`, `answers.yaml`, `tailored.ai.yaml` = AI draft, `tailored.yaml` = edited).
- Web UI: `tailorbirdcv/api.py` (FastAPI), `tailorbirdcv/ai.py` (prompts + fact-check repair loop), `tailorbirdcv/engine.py` (Settings → AI engine, `engine.ENGINES` via `SwitchingEngine`: five engines — subscriptions through a local CLI: headless `claude -p` with tools disabled, or `CodexCLIEngine` (`codex exec` on the ChatGPT login, locked down by `CODEX_ISOLATION`: read-only sandbox, approvals never, ephemeral, user config/rules/AGENTS.md ignored, web search, shell, browser, computer use, images, plugins and MCP off — its file-edit tool can only be sandboxed, not removed; `CODEX_MIN_VERSION`, checked by doctor); API keys: `OpenAIAPIEngine` (Responses API, `store=False`) and `OpenRouterEngine` (Chat Completions, default `anthropic/claude-sonnet-5.5` = the Anthropic default; `provider: require_parameters + data_collection deny + zdr` by default, `only: [anthropic]` when `openrouter_zdr` is off) get schemas through `engine.openai_schema` (strict: $refs inlined, every property required, optional ones nullable) and answers through `engine.strip_nulls`; or `AnthropicAPIEngine` with the user's key — structured outputs (`output_config` json_schema via `engine.api_schema`, which drops unsupported keywords), falling back to a non-forced tool call when the API rejects a schema; never forced `tool_choice` (Opus 5.5/Sonnet 5.5/Fable 5.1 reject it). Both CLI engines strip every provider's key (`engine._API_CREDENTIALS`: Anthropic, OpenAI, OpenRouter, Codex) from their environment (the CLIs would otherwise bill a key instead of the subscription); keys live only in the OS keychain via `apikey.py` (`PROVIDERS`: one account per provider) or the provider's environment variable, is never written to the data folder and never returned by the API, only masked; tests use an in-memory keyring from conftest), `tailorbirdcv/store.py`, `tailorbirdcv/jobfetch.py` (JD from URL: ATS APIs → JSON-LD → text → Playwright fallback, SSRF-guarded on every hop), `web/` (React + Vite + Tailwind). The model never writes to the profile: gap answers become *proposals* the user approves in the UI.

## Web API conventions
- Every `/api/*` request needs the access key: `tailorbirdcv serve` opens `/?key=<key>` (the key lives in `<data folder>/.access-key`, owner-only), which the middleware turns into an HttpOnly, SameSite=Strict `tailorbirdcv_key` cookie; without it the API answers 401 `{code: locked}` and the UI shows how to unlock. The TrustedHost (DNS-rebinding) check runs first. Every non-GET `/api/*` request must also send `X-TailorbirdCV: 1` (cross-site guard); any `/api/*` request with `Sec-Fetch-Site` other than `same-origin`/`none` is refused. Profile/knowledge/YAML PUTs must send `If-Match: <version>` (428 without; 409 means reload). The data folder is made owner-only (`oscompat.make_private`). Build, freeze and delete of one application take `store.app_lock(app_id)` (before `store.lock`).
- The headless browser runs with Chromium's sandbox on and WebRTC/WebTransport/QUIC disabled (`jobfetch._NO_SIDE_CHANNELS_JS`); fetching a job page is capped at 90 s.
- Private files are written atomically under a process-wide lock (`store.lock`); never hold it across an AI call.
- Deleted evidence/knowledge ids are retired (`retired_ids`) and never reused: saves that re-introduce one are rejected, and `ingest --force` keeps them (changed text gets a new id).
- URL fetching goes through `jobfetch.pinned_client()` (PinnedBackend: resolve once, validate every address, connect to the validated one). The headless browser's requests are performed by that client too, never by Chromium's network stack.
- The AI engine runs fully isolated (`engine.ISOLATION_ARGS`): no tools, MCP, user/local settings, plugins, hooks, skills or sessions.
- Hiring-manager review (`tailorbirdcv/critique.py`): on-demand verdict/scores/skim + issues pinned to claims by their original text; every suggested rewrite is fact-checked before it's shown (failures become advice); fixes needing new info become `hm-` questions in Gaps; accepted/rejected decisions live in `review.yaml` and feed style learning. The prompt also lists what the page prints from the profile (`critique.printed_sections`: sub-roles, projects, education, extras), so a degree or certificate on the page is never reported missing.
- Closing an application sets status `closed` plus an **outcome** (rejected, no_response, role_closed, withdrew, declined_offer, did_not_apply, accepted_offer); the stage it reached comes from its funnel milestones. Old `rejected`/`withdrawn` statuses migrate automatically.
- Builds record `built_hash` (the exact draft bytes rendered) and `built_profile` (a fingerprint of the profile parts that resume prints). Freezing requires both to match AND the current draft to pass the fact-check against the current profile.
- **AI steps run as tasks** (`api.run_task`; analyze, proposals, compose, trim, fill, critique, letter): one per application at a time (a second start → 409 `{code: running, task}`), held in memory (`tasks`; a restart ends them). The request still waits and answers as before, but through `asyncio.shield`, so leaving the page never cancels it; `POST …/task/stop` cancels it (the CLI process is killed, nothing is saved; the waiting request gets 409 `{code: stopped}`). A finished task (done/failed/stopped) stays until the page that shows its outcome sends `DELETE …/task`; for the steps that only suggest (`RESULT_KINDS`: trim, fill, proposals) it keeps the result for that page. `GET /applications/{id}` and the list carry `task`; `GET /tasks` lists them; an analysis that renames the application re-keys its task. Upgrade and restore also wait while any runs (`tasks_running`). UI: `Workspace` follows a running task it finds (polls, shows elapsed from the server's start), applies a finished one (`steps/taskResults.ts`, shared with the steps), and has Stop; each application gets its own page instance (`WorkspacePage`, keyed by `renamed.ts` so a rename keeps the page), so a late result never lands on another application; the board shows the step on the card; the tab title says when one finishes elsewhere (`App.useTaskTitle`).
- AI Trim never saves: `/trim` returns a fact-checked `trim_proposal` that the UI loads into Review as unsaved edits.
- Marking an application **applied** freezes a read-only copy of exactly what was sent (`sent/<timestamp>/`); stale or missing PDFs → "Build & freeze". Never edit `sent/`.
- Each sent copy records `fingerprints` in `sent.json` (SHA-256 per file; for PDFs also Word's XMP `xmpMM:DocumentID` and the trailer `/ID`). **Identify a PDF** (Applications, `POST /api/identify`, `tailorbirdcv/identify.py`) matches any PDF to its application: exact SHA-256 → same document id (re-saved) → closest text (≥ `TEXT_MIN`, a guess, never proof); copies frozen before fingerprints are fingerprinted on the fly, never written back. Nothing is ever added to the PDF.
- **Updates** (`tailorbirdcv/update.py`): `GET /api/update` compares the running version with PyPI's latest (`https://pypi.org/pypi/tailorbirdcv/json`, cached in `<data folder>/update.json` for 24 h; never fetched when `settings.update_check` is off; `TAILORBIRDCV_UPDATE_URL` overrides the URL for tests/CI only). `install_kind()` reads `sys.prefix/uv-receipt.toml`: only `uv-tool` (installed by name from PyPI) gets **Upgrade** (`POST /api/update/upgrade`, refused while any other non-GET request runs — `app.state.busy`); others get `COMMANDS[kind]`. Upgrade: the API sets `app.state.upgrade`, records `pending` and calls `app.state.request_exit` (set by `cmd_serve`); after the server stops, `cli.restart_after_upgrade` runs `uv tool upgrade tailorbirdcv` with the installer's uv settings — macOS/Linux in the same terminal then `os.execv` on the same port; Windows (locked files) writes `update/upgrade.ps1` (values only via env vars) and starts it in a new console, which waits for this process, upgrades and runs `tailorbirdcv serve` there. The next start's `update.settle` records `last_upgrade` (ok/error) for the UI; the log is `update/last-upgrade.log`. UI: `web/src/pages/UpdateBanner.tsx` (banner, full-page restart state, outcome) and Settings → About TailorbirdCV. CI job *Self-upgrade* runs it end to end on macOS and Windows (`.github/scripts/self_upgrade.py`).
- **Company icons** (`tailorbirdcv/favicon.py`): for an application made from a job link, the company's site icon is fetched once in the background (on create, and backfilled from `GET /applications` for older ones; one at a time, deduped) and kept as `<app>/favicon.<ext>` with `meta.favicon` (`""` = checked, none). Site: the link's own host, unless it's a job board (`favicon.BOARDS`): then the company's website from the posting's JobPosting `hiringOrganization` url/sameAs (`jobfetch.org_sites`, `Job.sites`), skipping boards and social profiles, else no icon. Every request goes through `jobfetch.safe_fetch` (the SSRF-guarded client); only images by their bytes (ICO/PNG/GIF/JPEG/WEBP, or SVG; ≤ 200 KB). Sites that give plain requests an empty page get one retry through the headless browser (`find_icon_rendered`: renders the homepage to find the icon's real address; the icon itself is still fetched by the guarded client). Served by `GET /api/applications/{id}/favicon` (nosniff, `default-src 'none'; style-src 'unsafe-inline'; sandbox`, so an SVG never runs scripts even when opened directly); never in `store.files()`, so never built, sent or frozen. `settings.company_icons` off = no icons shown and none fetched.
- **Privacy mode** (`tailorbirdcv/privacy.py`, experimental, `settings.hide_personal`, default on): **every AI call goes through `engine.PrivateEngine`** (api.create_app wraps whatever engine it gets; never call an engine around it). It redacts the system prompt and prompt with a per-call `privacy.Vault` (the profile's contact name/email/phone/links, `settings.private_address`, and `privacy.EXTRA` from the import's typed name/address; plus any email, phone (strict pattern, never resume metrics or dates; includes national formats: trunk-0 UK/FR/DE, SG/HK 4+4, IN 5+5), personal-profile link, or web address containing a distinctive name part) into placeholders (`[NAME]`, `[EMAIL 2]`…), and restores the JSON answer before anything reads it; when anything was hidden the system prompt also gets `privacy.PLACEHOLDER_NOTE` (copy placeholders exactly; the AI once dropped `[NAME]`), and the CV import falls back to the name the user typed (fact-check, `importer.unverified` and the renderer are unchanged). `ai.profile_text` always leaves `contact` out, switch or not. `POST /api/profile/import` requires `name` while the switch is on. Settings → Privacy shows `GET /api/privacy/preview`. City/country and career history are not hidden; other people's names aren't detected.
- **Backup & restore** (`tailorbirdcv/backup.py`; Settings → Backup & restore, the setup wizard's welcome page, `tailorbirdcv backup|restore`): a plain .zip (not encrypted, by the owner's choice) of the allowlisted user data (`backup.INCLUDE`: profile, knowledge, settings, history, applications incl. `sent/`, source, config) plus a manifest (`format`, SHA-256 per file); never this computer's files (`.access-key`, `word/`, `libreoffice/`, `update*`, `calibration.json`). API keys only on request (`GET /api/backup?keys=true` → `keys.json`; restored into the keychain). Restore (`POST /api/restore`, body = the zip; refused while anything else runs) validates everything first (format, safe paths, sizes, checksums, a loadable profile), stages next to the data, then swaps it in under `store.lock`; the replaced data goes to `before-restore/<time>/`, never deleted. Every backup ends with `backup.WARNING` (UI and CLI): unencrypted, may hold API keys, keep it safe.
- **Memory** (`knowledge.yaml`, never citable): finalized gap answers (`store._remember`) and style preferences. **One answer per topic**: `store.merge_answers` keeps the newest across applications on the same topic or question (`store.topic_key`), and an answer to a pre-filled question replaces the one it came from — except "no experience" never replaces an older "experience" answer (that one holds detail); `store.compact_knowledge` tidies older files at startup (saved with history). **Known gaps expire**: a `no_experience` answer older than `ai.KNOWN_GAP_DAYS` (180) is marked `stale` in the analysis prompt and asked again with its id pre-filled; `analyze` turns any stale known gap the model still lists into such a question. **Style learning**: marking an application applied (`PATCH` status or `freeze?mark_applied`) queues `learn_style_quietly` in the background (`settings.learn_style`, default on): it compares the AI drafts with what was sent (`ai.edited_claims` + `ai.edited_letter`), plus guidance and rejected review fixes, and adds *proposed* preferences (never active until approved); `meta.style_learned` (a fingerprint of that material) means each version is studied once; `GET /applications/{id}` reports `learning_style`. The Export step's StyleCoach shows them; Applications shows a notice while any are waiting.
- Every save of `profile.yaml`/`knowledge.yaml` keeps the previous version in `private/history/` (content changes only; kept forever); restore is itself undoable and merges `retired_ids`.
- PDFs come from **Microsoft Word or LibreOffice** (`pdf.py`), chosen in Settings (`private/settings.json`, `GET/PUT /api/settings`); when both are installed Word is the default, and a chosen engine that's missing falls back to the other. One conversion runs at a time (thread lock + `oscompat.FileLock` in `private/word/`, so CLI and server take turns), always in that fixed folder (Word's macOS sandbox "Grant File Access" prompt appears at most once).
  - Word, macOS: `osascript` JXA — launched hidden in the background, never activated; our document is addressed only by its unique name (never by position), and Word is quit only if TailorbirdCV started it and its document count is 0 (`saving: ask`).
  - Word, Windows: PowerShell 5.1 COM (`-EncodedCommand`) — our document opens with `Visible=$false`, is closed through its own object, and Word is quit only if TailorbirdCV created that instance and `Documents.Count -eq 0`. No Word on Linux.
  - LibreOffice runs headless with its own profile (`private/libreoffice/`); fonts the docx names are symlinked (copied on Windows) into the profile, and a font this machine lacks gets a metric-compatible stand-in through a replacement rule in the profile (Georgia → Gelasio, bundled in `tailorbirdcv/data/fonts`; Calibri → Carlito). Digit ranges ("2–4") inside `<w:t>` text runs are glued with U+2060 in LibreOffice's copy only — never in the user's .docx.
- OS differences live in `tailorbirdcv/oscompat.py` (file lock, process-tree kill, read-only-safe `rmtree`, retrying `replace`, reveal in Finder/Explorer/file manager). Files are written with `\n` line endings so hashes match across OSes; folder slugs never use Windows-reserved names (`con`, `nul`, `com1`…).
- **Cover letter** (per application, Workspace step "Cover letter", `web/src/pages/steps/CoverLetter.tsx`): `schema.CoverLetter` (tone formal|warm|direct, optional `recipient`, paragraphs of `LetterSentence{text, kind, sources}`) in `<app>/letter.yaml` (`letter.ai.yaml` = AI draft). `ai.compose_letter` drafts the body only (fenced posting, the tailored resume's claims first, repair loop up to `MAX_REPAIR_ROUNDS` on `factcheck.check_letter`); greeting, closing line and sign-off come from `render.LETTER_CLOSINGS`/`letter_greeting` by tone, the header from the profile (`render._header`, shared with the resume). `factcheck.check_letter` checks by kind: `evidence` = `check_claim` like a highlight; `posting` = only the job description's words/numbers/names plus `MOTIVATION_WORDS`, never experience (`_EXPERIENCE_CLAIM`) or invented feelings (`_INVENTED_FEELING`); `link` = ≤ 20 words, no facts, one per paragraph; all: `INJECTION_RE`; ≤ `LETTER_MAX_WORDS` words; company/role names from the analysis allowed (`_neutral`). Files `<Name>_Cover_Letter.docx/.pdf` (`store.LETTER_SUFFIX`): `clear_outputs(letter=)` only ever deletes its own kind; a letter over one page is never kept; `letter_built_hash`/`letter_built_profile` → `letter_stale`; a *built* letter must be current and pass to freeze (`letter_problem`), Build & freeze rebuilds it, and the sent copy includes it plus `letter.yaml`. Endpoints `POST/PUT/DELETE /applications/{id}/letter`, `POST …/letter/build`.
- **Prompt injection** (a job posting is untrusted): (1) the fact-check refuses a claim whose meaningful words mostly aren't in its cited sources (`factcheck.evidence_overlap` ≥ `OVERLAP_MIN` 0.5 for claims of ≥ 4 words; sources + approved synonyms of terms they use, + skills for summary/highlights; real claims measure ≥ 0.69) and text addressed to a reader or an AI (`factcheck.INJECTION_RE`) unless the evidence says it; (2) every prompt carries job-derived text (JD, analysis, must-haves, role brief, gap answers) inside `ai.untrusted(label, text)` fences with a random tag, and `system_prompt` says fenced text is data, never instructions; (3) `jobfetch` leaves out text hidden from people (`_drop_hidden`: ~0 font size, transparent, screen-reader-only/off-screen; the browser path checks computed styles before removing the page's CSS) but keeps collapsed tabs (display:none). Tests: `tests/test_injection.py`.
- Fact-check strictness (`factcheck.py`): authority/ownership/credential/scope words are checked in every form (`_STEMS`; a leadership word needs an equal or stronger one in the evidence itself, not the role's title); a number must appear with what it counts in a single cited source (`_number_mentions`/`_paired_in`; a role's dates are only years); a title next to an employer must be that employer's (`_check_title_pairs`); approved vocabulary applies to the summary and highlights only; competency labels allow only structural words (`LABEL_WORDS`) unless the profile supports the word. Import verification (`importer.unverified`) keeps symbols and decimals as part of words, aligns the run-together fallback with word boundaries, and checks each role inside its own part of the CV (`_role_sections`: each heading belongs to one role, in CV order, so a promotion at the same employer isn't flagged).
- The fact-check's word list is bundled (`tailorbirdcv/data/words.txt.gz`, public-domain web2 — the same list macOS ships), so the gate behaves identically on every OS. CI (`.github/workflows/ci.yml`) runs the tests on macOS, Windows and Linux, plus real LibreOffice conversions on Linux and Windows.
- **Targets** (`settings.json` → `targets`: field, seniority, roles, region, spelling, pages, pack) become an `ai.Context`, set per API request by the middleware; prompts use `ai.system_prompt()` and `ai.pages_text()`, never hard-coded domain, region, spelling or page counts. Emphasis config resolves `<data folder>/config/<name>` (personal override) → `tailorbirdcv/data/config/packs/<pack>/<name>` → `tailorbirdcv/data/config/<name>` (general). The analysis' industry enum is the active config's keys. Packs (`ai.PACKS`, names in `Settings.tsx` `PACK_NAMES`): cybersecurity, software_engineering, data_ai, product_management, project_management, technical_program_management; each has `industries.yaml` (signals, lead_with, mirror_terms, surface, tone) and `tracks.yaml` (manager, ic, hybrid), generic only (no one's employers or projects). The setup wizard suggests one from the CV's field or target roles (`importer.suggested_pack`, most specific first).
- **First run = the setup wizard** (`/setup`, `web/src/pages/setup/`): welcome → your computer → connect your AI → upload CV → review → targets → design → final checks. "Your computer" is `GET /api/doctor?phase=setup` (`doctor.run_checks`): every AI option's state, data folder, PDF engine, keychain, headless browser and Node, each with a `level` (required / recommended / optional / info, independent of status) and an optional `action` (`test-pdf` → `POST /api/pdf/test`, `install-browser`, `test-ai` → `POST /api/engine/test`, one tiny real call); the shared `web/src/pages/SystemCheck.tsx` renders it (re-checking every few seconds while something required or recommended is missing) in the wizard, Final checks and Settings. The UI sends anyone without a profile *and* `setup.completed` there (an install with a profile but no `setup` state counts as completed). State lives in `settings.json` → `setup` (`store.setup_state`; `save_settings` preserves it); the import draft (profile, `unverified`, source text, suggested targets, PDF page count) lives in `<data folder>/setup/draft.json` until finish/start over, so a refresh never loses it.
  - `POST /api/profile/import` has the AI *transcribe* the CV (`importer.py`: verbatim, no ids, plus `suggested_targets`); TailorbirdCV assigns ids like `ingest`. `importer.unverified` checks **every** field (contact, links, headline, skills incl. categories, role employer/location/title/dates, evidence, lead items) as whole words in order (`_Source.has`; the no-space fallback only for long items).
  - `POST /api/profile/create` re-verifies on the server against the stored source: any unverified path not listed in `confirmed` → 422 `{code: unconfirmed, paths}`. Confirmed evidence gets `note: importer.CONFIRMED_NOTE`. Blank: `{"blank": {name, location, headline}}`. Every profile needs at least one headline (an import without one uses the latest job title).
- **Themes** (`themes.py`: classic, modern, compact), **paper** (letter/a4) and **text size** (`themes.TEXT_SIZES`: standard = as designed; comfortable = body, dates, section titles and companies 1 pt larger; the default) are settings. **No text below 9.5 pt** (`themes.MIN_SIZE`) in any design except Classic at the Standard size (the original's 8.5 pt contact line and dates); a contact line too long for 9.5 pt wraps between items only (no-break spaces inside items, the separator ends the line; not in Classic Standard); `render.use_design(theme, paper, text_size)` applies all three, and calibration/fill keys include the size (`fit.design_key`, e.g. `modern+comfortable/a4`); the API middleware and CLI set them per request with `render.use_design`, and `ai` uses the active design's characters-per-line and lines-per-page for estimates and budgets. **Classic must stay byte-identical** to the original design: `tests/fixtures/golden_classic_document.xml` guards it. Headings (section titles, company lines, job titles, scope lines) carry `keepNext` so they're never stranded at the bottom of a page, and the header (name, headline, contact line; `render._header`, shared with the cover letter) is centered in every design (`_Builder._para(center=True)`): those are the only deliberate differences from the original. Theme fonts must have metric-compatible open substitutes shipped in `tailorbirdcv/data/fonts` (Calibri → Carlito, Georgia → Gelasio).
- **Section headings** are a setting (`settings.section_titles`, Settings → Resume design; "" = the design's own `themes.TITLES`; applied by `render.use_design`). A new profile gets `themes.NEW_PROFILE_TITLES` (PROJECTS, ADDITIONAL INFORMATION); profiles made earlier keep `TITLES`, and Classic's golden render is unchanged.
- Output files are named from the profile name (`store.file_safe_name`: accents dropped, any script kept).
- **Length estimate** (`tailorbirdcv/layout.py`): `ai.estimate_lines` lays the rendered .docx out the way Word does — each run wrapped with the real character widths of the bundled stand-in fonts at its own size and indent, line heights from the real fonts (`layout.LINE`: Calibri 1.2207 em, Georgia 1.1362 em; Gelasio's own is 1.66), the larger of space-after and the next space-before between paragraphs, bottom rules, paragraphs never split (keepLines) and keepNext headings moved with what follows — and returns body lines including page-break waste. It predicts the PDF to within ~1–2% (always on the long side) on Word and LibreOffice; re-check with a sweep of designs × page limits against real PDFs when changing the renderer or themes.
- Compose fits the draft to the length budget (`ai.length_budget`: `ai.FIT` (97%) of what the page limit holds in the active design, `ai.lines_per_page()`; a base resume only calibrates words per line, never shrinks the budget) with automatic trim rounds; the PDF engine's page count is the final check. **Recent roles keep a bullet**: `factcheck.bullet_roles` (roles with evidence that ended within `factcheck.RECENT_YEARS`, 10, by `end_year`; "Present" = this year) are named in the compose and trim prompts (`ai._keep_bullets_rule`), a trim that leaves one without bullets is discarded (`ai._emptied`), and the fact-check warns (never blocks) when one has none. Older roles may be just their scope line. **No repeats**: the compose prompt forbids restating a bullet as a highlight, trim drops such a bullet first and cuts duty wording before outcomes (results, numbers, scale, adoption), fill never adds a line that restates one, and `factcheck.repeated_highlights` (either line shares ≥ `REPEAT_MIN` 0.55 of the other's meaningful words) warns, never blocks.
- **Page fill** (`tailorbirdcv/fit.py`): after every PDF build, `ai.measure_pdf` measures how far down each page the text reaches (meta `fill`: `{pages: [0-1…], room}`) and teaches that design (`fit.design_key`) its real lines-per-page in `<data folder>/calibration.json` (moving average, clamped 0.8–1.3; entries carry `model: fit.MODEL`, so factors learned by an older estimate are ignored). `POST /api/applications/{id}/fill` ("Fill the page with AI" in Export, offered when the fresh build's last page has ≥ 5 free lines) adds relevant unused evidence up to that room, fact-checked and never saved: like `/trim`, it returns a `fill_proposal` the UI loads into Review; evidence the user removed from the AI draft is never added back.
