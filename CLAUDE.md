# AutoCV

Tailors the user's resume to a job description without inventing anything. A local web app (macOS, Windows, Linux) for anyone: who the resume is for (field, seniority, target roles, region, spelling, page limit, domain pack) is a setting (Settings → Your targets), never hard-coded. A gitignored `CLAUDE.local.md` may hold the owner's personal context.

## Non-negotiable rules
1. **Never invent.** Every claim in a tailored resume must trace to the master profile (`profile.yaml` in the data folder). No new numbers, tools, employers, scope, outcomes, or implied experience — not even "familiar with". If the JD wants something the profile lacks, **ask the user**; if they have no real experience, it stays a gap.
2. **Locked fields never change**: contact, employer, location, job title, dates, education, certifications, awards, languages. The renderer pulls them from the profile by id — never retype them.
3. **The profile changes only with the user's explicit confirmation of the exact wording.** (The first-run import shows the transcribed profile, flags anything not found word-for-word in the source file, and saves only when the user clicks Save.) New evidence gets `source: interview` or `source: prep_guide` and `in_base_resume: false`.
4. **Rephrasing is allowed** (reorder, merge, trim, mirror JD vocabulary) as long as the meaning, numbers and entities are unchanged and each claim cites its `sources`. Don't upgrade verbs ("contributed to" → "led") or scope ("team" → "organization").
5. `uv run autocv check` must PASS before `build`. Bullets may only cite their own role's evidence; role header ids aren't citable. Fix violations by citing the right evidence or rewording; never by adding vocabulary or synonyms without the user's approval.
6. Personal data lives only in the data folder (`private/` in a checkout, gitignored; the OS per-user folder when installed). Never commit it, never paste it into tests or shipped files (`autocv/data/`, demo, examples) — tests use `tests/fixtures/` (fictional, and not a lightly disguised owner: no real employers, places, numbers or project names from anyone's actual CV). `test_shipped_config_has_no_personal_data` reads the owner's private profile at test time (never copied anywhere) to check shipped config.

## Layout
- `autocv/` — `schema.py` (models), `ingest.py` (docx → profile), `render.py` (docx in a theme), `themes.py` (resume designs), `factcheck.py` (blocking gate), `ats.py` (keyword coverage), `pdf.py` (Word/LibreOffice → PDF), `cli.py`.
- `autocv/data/` (shipped in the package): `config/industries.yaml`, `config/tracks.yaml` — emphasis heuristics only, never facts; `templates/base.docx` — theme/page setup with empty body, no PII; `fonts/` (Gelasio, OFL); `words.txt.gz` (fact-check word list). Never put personal data here.
- `autocv/paths.py` — where things live: bundled data, the built UI (`autocv/web/` in a wheel, `web/dist/` in a checkout), and the user's data (`AUTOCV_PRIVATE`, else `./private` in a checkout that has one, else the OS per-user data folder via platformdirs).
- Packaging: PyPI name `autocv-app` (commands `autocv` and `autocv-app`); `hatch_build.py` puts `web/dist` into the wheel as `autocv/web` (run the web build first). `autocv/doctor.py` backs `autocv doctor` and `GET /api/doctor`. Version: the root `VERSION` file (hatch reads it; `[tool.uv] cache-keys` refreshes the editable install). Releases: bump `VERSION` on main → once CI passes, `.github/workflows/release.yml` (`workflow_run`) builds that commit, publishes to PyPI (trusted publishing) and pushes tag `vX.Y.Z`; it skips commits whose version is already tagged and refuses a lower version; the automatic path only runs when the repo variable `RELEASES_ENABLED` is `true`. A manual `vX.Y.Z` tag push still works (must match `VERSION`). `install.sh` (macOS/Linux, POSIX sh) and `install.ps1` (Windows PowerShell 5.1 + 7, ASCII only, never `exit`: it runs inside the user's shell via `iex`) install uv if missing, then `uv tool install --upgrade --python 3.13 autocv-app` (`AUTOCV_PACKAGE` overrides) with `UV_MANAGED_PYTHON` and system certificates, fix PATH and start `autocv serve`; they refuse while AutoCV runs (Windows locks its files) and under sudo; CI's *One-line installer* job runs them piped against the commit's wheel. No licence has been chosen yet: don't add one.
- `.claude/skills/profile` (`/profile`) and `.claude/skills/tailor` (`/tailor`).
- `private/` (the data folder) — `profile.yaml` (source of truth), `knowledge.yaml` (memory: past gap answers + approved style preferences, **never citable**), `source/`, `applications/<company>/<yyyy-mm-dd>_<role>/` (id `<company>~<yyyy-mm-dd>_<role>`; `meta.json`, `answers.yaml`, `tailored.ai.yaml` = AI draft, `tailored.yaml` = edited).
- Web UI: `autocv/api.py` (FastAPI), `autocv/ai.py` (prompts + fact-check repair loop), `autocv/engine.py` (Settings → AI engine, `engine.ENGINES` via `SwitchingEngine`: five engines — subscriptions through a local CLI: headless `claude -p` with tools disabled, or `CodexCLIEngine` (`codex exec` on the ChatGPT login, locked down by `CODEX_ISOLATION`: read-only sandbox, approvals never, ephemeral, user config/rules/AGENTS.md ignored, web search, shell, browser, computer use, images, plugins and MCP off — its file-edit tool can only be sandboxed, not removed; `CODEX_MIN_VERSION`, checked by doctor); API keys: `OpenAIAPIEngine` (Responses API, `store=False`) and `OpenRouterEngine` (Chat Completions, default `anthropic/claude-sonnet-5.5` = the Anthropic default; `provider: require_parameters + data_collection deny + zdr` by default, `only: [anthropic]` when `openrouter_zdr` is off) get schemas through `engine.openai_schema` (strict: $refs inlined, every property required, optional ones nullable) and answers through `engine.strip_nulls`; or `AnthropicAPIEngine` with the user's key — structured outputs (`output_config` json_schema via `engine.api_schema`, which drops unsupported keywords), falling back to a non-forced tool call when the API rejects a schema; never forced `tool_choice` (Opus 5.5/Sonnet 5.5/Fable 5.1 reject it). Both CLI engines strip every provider's key (`engine._API_CREDENTIALS`: Anthropic, OpenAI, OpenRouter, Codex) from their environment (the CLIs would otherwise bill a key instead of the subscription); keys live only in the OS keychain via `apikey.py` (`PROVIDERS`: one account per provider) or the provider's environment variable, is never written to the data folder and never returned by the API, only masked; tests use an in-memory keyring from conftest), `autocv/store.py`, `autocv/jobfetch.py` (JD from URL: ATS APIs → JSON-LD → text → Playwright fallback, SSRF-guarded on every hop), `web/` (React + Vite + Tailwind). The model never writes to the profile: gap answers become *proposals* the user approves in the UI.

## Web API conventions
- Every `/api/*` request needs the access key: `autocv serve` opens `/?key=<key>` (the key lives in `<data folder>/.access-key`, owner-only), which the middleware turns into an HttpOnly, SameSite=Strict `autocv_key` cookie; without it the API answers 401 `{code: locked}` and the UI shows how to unlock. The TrustedHost (DNS-rebinding) check runs first. Every non-GET `/api/*` request must also send `X-AutoCV: 1` (cross-site guard); any `/api/*` request with `Sec-Fetch-Site` other than `same-origin`/`none` is refused. Profile/knowledge/YAML PUTs must send `If-Match: <version>` (428 without; 409 means reload). The data folder is made owner-only (`oscompat.make_private`). Build, freeze and delete of one application take `store.app_lock(app_id)` (before `store.lock`).
- The headless browser runs with Chromium's sandbox on and WebRTC/WebTransport/QUIC disabled (`jobfetch._NO_SIDE_CHANNELS_JS`); fetching a job page is capped at 90 s.
- Private files are written atomically under a process-wide lock (`store.lock`); never hold it across an AI call.
- Deleted evidence/knowledge ids are retired (`retired_ids`) and never reused: saves that re-introduce one are rejected, and `ingest --force` keeps them (changed text gets a new id).
- URL fetching goes through `jobfetch.pinned_client()` (PinnedBackend: resolve once, validate every address, connect to the validated one). The headless browser's requests are performed by that client too, never by Chromium's network stack.
- The AI engine runs fully isolated (`engine.ISOLATION_ARGS`): no tools, MCP, user/local settings, plugins, hooks, skills or sessions.
- Hiring-manager review (`autocv/critique.py`): on-demand verdict/scores/skim + issues pinned to claims by their original text; every suggested rewrite is fact-checked before it's shown (failures become advice); fixes needing new info become `hm-` questions in Gaps; accepted/rejected decisions live in `review.yaml` and feed style learning.
- Closing an application sets status `closed` plus an **outcome** (rejected, no_response, role_closed, withdrew, declined_offer, did_not_apply, accepted_offer); the stage it reached comes from its funnel milestones. Old `rejected`/`withdrawn` statuses migrate automatically.
- Builds record `built_hash` (the exact draft bytes rendered) and `built_profile` (a fingerprint of the profile parts that resume prints). Freezing requires both to match AND the current draft to pass the fact-check against the current profile.
- AI Trim never saves: `/trim` returns a fact-checked `trim_proposal` that the UI loads into Review as unsaved edits.
- Marking an application **applied** freezes a read-only copy of exactly what was sent (`sent/<timestamp>/`); stale or missing PDFs → "Build & freeze". Never edit `sent/`.
- Each sent copy records `fingerprints` in `sent.json` (SHA-256 per file; for PDFs also Word's XMP `xmpMM:DocumentID` and the trailer `/ID`). **Identify a PDF** (Applications, `POST /api/identify`, `autocv/identify.py`) matches any PDF to its application: exact SHA-256 → same document id (re-saved) → closest text (≥ `TEXT_MIN`, a guess, never proof); copies frozen before fingerprints are fingerprinted on the fly, never written back. Nothing is ever added to the PDF.
- **Updates** (`autocv/update.py`): `GET /api/update` compares the running version with PyPI's latest (`https://pypi.org/pypi/autocv-app/json`, cached in `<data folder>/update.json` for 24 h; never fetched when `settings.update_check` is off; `AUTOCV_UPDATE_URL` overrides the URL for tests/CI only). `install_kind()` reads `sys.prefix/uv-receipt.toml`: only `uv-tool` (installed by name from PyPI) gets **Upgrade** (`POST /api/update/upgrade`, refused while any other non-GET request runs — `app.state.busy`); others get `COMMANDS[kind]`. Upgrade: the API sets `app.state.upgrade`, records `pending` and calls `app.state.request_exit` (set by `cmd_serve`); after the server stops, `cli.restart_after_upgrade` runs `uv tool upgrade autocv-app` with the installer's uv settings — macOS/Linux in the same terminal then `os.execv` on the same port; Windows (locked files) writes `update/upgrade.ps1` (values only via env vars) and starts it in a new console, which waits for this process, upgrades and runs `autocv serve` there. The next start's `update.settle` records `last_upgrade` (ok/error) for the UI; the log is `update/last-upgrade.log`. UI: `web/src/pages/UpdateBanner.tsx` (banner, full-page restart state, outcome) and Settings → About AutoCV. CI job *Self-upgrade* runs it end to end on macOS and Windows (`.github/scripts/self_upgrade.py`).
- **Company icons** (`autocv/favicon.py`): for an application made from a job link, the company's site icon is fetched once in the background (on create, and backfilled from `GET /applications` for older ones; one at a time, deduped) and kept as `<app>/favicon.<ext>` with `meta.favicon` (`""` = checked, none). Site: the link's own host, unless it's a job board (`favicon.BOARDS`): then the company's website from the posting's JobPosting `hiringOrganization` url/sameAs (`jobfetch.org_sites`, `Job.sites`), skipping boards and social profiles, else no icon. Every request goes through `jobfetch.safe_fetch` (the SSRF-guarded client); only raster images (ICO/PNG/GIF/JPEG/WEBP by magic bytes, ≤ 200 KB), never SVG. Served by `GET /api/applications/{id}/favicon` (nosniff, `default-src 'none'`); never in `store.files()`, so never built, sent or frozen. `settings.company_icons` off = no icons shown and none fetched.
- Every save of `profile.yaml`/`knowledge.yaml` keeps the previous version in `private/history/` (content changes only; kept forever); restore is itself undoable and merges `retired_ids`.
- PDFs come from **Microsoft Word or LibreOffice** (`pdf.py`), chosen in Settings (`private/settings.json`, `GET/PUT /api/settings`); when both are installed Word is the default, and a chosen engine that's missing falls back to the other. One conversion runs at a time (thread lock + `oscompat.FileLock` in `private/word/`, so CLI and server take turns), always in that fixed folder (Word's macOS sandbox "Grant File Access" prompt appears at most once).
  - Word, macOS: `osascript` JXA — launched hidden in the background, never activated; our document is addressed only by its unique name (never by position), and Word is quit only if AutoCV started it and its document count is 0 (`saving: ask`).
  - Word, Windows: PowerShell 5.1 COM (`-EncodedCommand`) — our document opens with `Visible=$false`, is closed through its own object, and Word is quit only if AutoCV created that instance and `Documents.Count -eq 0`. No Word on Linux.
  - LibreOffice runs headless with its own profile (`private/libreoffice/`); fonts the docx names are symlinked (copied on Windows) into the profile, and a font this machine lacks gets a metric-compatible stand-in through a replacement rule in the profile (Georgia → Gelasio, bundled in `autocv/data/fonts`; Calibri → Carlito). Digit ranges ("2–4") inside `<w:t>` text runs are glued with U+2060 in LibreOffice's copy only — never in the user's .docx.
- OS differences live in `autocv/oscompat.py` (file lock, process-tree kill, read-only-safe `rmtree`, retrying `replace`, reveal in Finder/Explorer/file manager). Files are written with `\n` line endings so hashes match across OSes; folder slugs never use Windows-reserved names (`con`, `nul`, `com1`…).
- Fact-check strictness (`factcheck.py`): authority/ownership/credential/scope words are checked in every form (`_STEMS`; a leadership word needs an equal or stronger one in the evidence itself, not the role's title); a number must appear with what it counts in a single cited source (`_number_mentions`/`_paired_in`; a role's dates are only years); a title next to an employer must be that employer's (`_check_title_pairs`); approved vocabulary applies to the summary and highlights only; competency labels allow only structural words (`LABEL_WORDS`) unless the profile supports the word. Import verification (`importer.unverified`) keeps symbols and decimals as part of words, aligns the run-together fallback with word boundaries, and checks each role inside its own part of the CV (`_role_sections`).
- The fact-check's word list is bundled (`autocv/data/words.txt.gz`, public-domain web2 — the same list macOS ships), so the gate behaves identically on every OS. CI (`.github/workflows/ci.yml`) runs the tests on macOS, Windows and Linux, plus real LibreOffice conversions on Linux and Windows.
- **Targets** (`settings.json` → `targets`: field, seniority, roles, region, spelling, pages, pack) become an `ai.Context`, set per API request by the middleware; prompts use `ai.system_prompt()` and `ai.pages_text()`, never hard-coded domain, region, spelling or page counts. Emphasis config resolves `<data folder>/config/<name>` (personal override) → `autocv/data/config/packs/<pack>/<name>` → `autocv/data/config/<name>` (general). The analysis' industry enum is the active config's keys.
- **First run = the setup wizard** (`/setup`, `web/src/pages/setup/`): welcome → your computer → connect your AI → upload CV → review → targets → design → final checks. "Your computer" is `GET /api/doctor?phase=setup` (`doctor.run_checks`): every AI option's state, data folder, PDF engine, keychain, headless browser and Node, each with a `level` (required / recommended / optional / info, independent of status) and an optional `action` (`test-pdf` → `POST /api/pdf/test`, `install-browser`, `test-ai` → `POST /api/engine/test`, one tiny real call); the shared `web/src/pages/SystemCheck.tsx` renders it (re-checking every few seconds while something required or recommended is missing) in the wizard, Final checks and Settings. The UI sends anyone without a profile *and* `setup.completed` there (an install with a profile but no `setup` state counts as completed). State lives in `settings.json` → `setup` (`store.setup_state`; `save_settings` preserves it); the import draft (profile, `unverified`, source text, suggested targets, PDF page count) lives in `<data folder>/setup/draft.json` until finish/start over, so a refresh never loses it.
  - `POST /api/profile/import` has the AI *transcribe* the CV (`importer.py`: verbatim, no ids, plus `suggested_targets`); AutoCV assigns ids like `ingest`. `importer.unverified` checks **every** field (contact, links, headline, skills incl. categories, role employer/location/title/dates, evidence, lead items) as whole words in order (`_Source.has`; the no-space fallback only for long items).
  - `POST /api/profile/create` re-verifies on the server against the stored source: any unverified path not listed in `confirmed` → 422 `{code: unconfirmed, paths}`. Confirmed evidence gets `note: importer.CONFIRMED_NOTE`. Blank: `{"blank": {name, location, headline}}`. Every profile needs at least one headline (an import without one uses the latest job title).
- **Themes** (`themes.py`: classic, modern, compact), **paper** (letter/a4) and **text size** (`themes.TEXT_SIZES`: standard = as designed; comfortable = body, dates, section titles and companies 1 pt larger, contact line unchanged; the default) are settings; `render.use_design(theme, paper, text_size)` applies all three, and calibration/fill keys include the size (`fit.design_key`, e.g. `modern+comfortable/a4`); the API middleware and CLI set them per request with `render.use_design`, and `ai` uses the active theme's characters-per-line and lines-per-page for estimates and budgets. **Classic must stay byte-identical** to the original design: `tests/fixtures/golden_classic_document.xml` guards it. Headings (section titles, company lines, job titles, scope lines) carry `keepNext` so they're never stranded at the bottom of a page; that is the only deliberate difference from the original. Theme fonts must have metric-compatible open substitutes shipped in `autocv/data/fonts` (Calibri → Carlito, Georgia → Gelasio).
- Output files are named from the profile name (`store.file_safe_name`: accents dropped, any script kept).
- Compose fits the draft to the length budget (`ai.length_budget`: what the page limit holds in the active theme and paper, `ai.lines_per_page()`; a base resume only calibrates words per line, never shrinks the budget) with automatic trim rounds; the PDF engine's page count is the final check.
- **Page fill** (`autocv/fit.py`): after every PDF build, `ai.measure_pdf` measures how far down each page the text reaches (meta `fill`: `{pages: [0-1…], room}`) and teaches that design (`theme/paper`) its real lines-per-page in `<data folder>/calibration.json` (moving average, clamped 0.8–1.3). `POST /api/applications/{id}/fill` ("Fill the page with AI" in Export, offered when the fresh build's last page has ≥ 5 free lines) adds relevant unused evidence up to that room, fact-checked and never saved: like `/trim`, it returns a `fill_proposal` the UI loads into Review; evidence the user removed from the AI draft is never added back.

## Commands
```
uv run autocv ingest | baseline | new "<Co>" "<Role>" | evidence [term] | check <app> | build <app> | serve | doctor | install-browser
uv run pytest
npm --prefix web run build && uv build   # wheel + sdist in dist/ (the wheel includes the UI)
npm --prefix web run build      # then `uv run autocv serve` → http://127.0.0.1:8000
AUTOCV_ENGINE=fake uv run autocv serve --port 8001   # demo engine, no AI calls
```
